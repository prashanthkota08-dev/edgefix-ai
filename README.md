# EDGEFIX AI — Offline Multimodal Field Technician Copilot

**See it. Ask it. Fix it — offline.** EdgeFix AI is an offline-first multimodal field technician copilot for maintenance work when cloud connectivity is unreliable. It combines a photo and technician question with local technical-manual retrieval, evidence fusion, and grounded reasoning.

## Problem and solution

Field technicians need equipment context and maintenance guidance where cloud access may be unavailable. EdgeFix keeps its core demonstration workflow local: an image and question are paired with page-aware retrieval from local PDFs. It presents source evidence, suggested checks, safety, and uncertainty so the user can review the basis of the response.

## Key features

- **CLIP vision:** local image/text comparison returns relative visual similarity signals, not calibrated probabilities, confirmed component identification, or a diagnosis.
- **Local RAG:** PDF text is indexed and retrieved locally with document, page, and section provenance.
- **Evidence fusion:** combines the question, optional visual observations, and retrieved passages.
- **Grounded reasoning:** extracts checks from retrieved content and includes sources, safety guidance, and uncertainty.
- **Offline CPU fallbacks:** transparent TF-IDF retrieval and deterministic reasoning work without a cloud service; semantic retrieval and Ollama are optional.
- **Snapdragon target path:** ONNX export and optional Qualcomm AI Hub integration are provided for future target validation.

The four included maintenance manuals are original synthetic demonstration documents, generated by `scripts/generate_sample_manuals.py`. They are not manufacturer instructions. The sample motor image is also generated by `scripts/create_sample_motor_image.py`.

## Architecture and offline workflow

```text
Image + question
    → local CLIP visual similarity signal
    → local PDF RAG retrieval
    → evidence fusion
    → local reasoning
    → grounded response with checks, safety, uncertainty, and sources
```

PyMuPDF extracts PDF text into page-aware chunks. The default standard-library TF-IDF retriever uses the local JSON index. Optional sentence-transformers semantic search uses cached local model weights and falls back to TF-IDF if unavailable. The deterministic reasoner uses retrieved content; optional Ollama runs on the local machine. No cloud inference key is required for the normal application.

## Windows installation

Use Python 3.11 or newer and open PowerShell in the repository directory. If the Python launcher is available:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup_windows.ps1
```

If Python is not on `PATH`, set `EDGEFIX_PYTHON` to a Python executable before setup. The setup script creates `.venv`, generates the four synthetic PDFs, builds the local index, and installs base dependencies.

CLIP support is optional and requires a one-time model download while online. To install and cache the CPU model and run a local inference check:

```powershell
.\scripts\setup_clip_windows.ps1
```

Or use `.\scripts\setup_windows.ps1 -WithClip`. Keep the Hugging Face cache local; model weights are excluded from Git. Check model licensing before redistribution.

## Run the application

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Streamlit prints a local URL. No cloud service is required for the normal workflow after setup and model caching. `EDGEFIX_OFFLINE=1` forces Hugging Face local-only model loading.

## Demo workflow

1. Open the Dashboard and review local CPU, offline, knowledge-base, benchmark, and Snapdragon validation status.
2. Open **Show me and tell me**, upload `data/sample_images/sample_motor.png`, and ask: “What should I inspect if this motor is overheating?”
3. Review **VISUAL OBSERVATION**, **DOCUMENT EVIDENCE**, recommended checks, safety, uncertainty, and cited sources.
4. Treat CLIP results as visual similarity signals only. The demo manuals are synthetic content, not manufacturer guidance.

A timestamped three-minute narration is in `docs/demo_script.md`.

## Snapdragon optimization path and Qualcomm AI Hub

- **Development:** Intel CPU.
- **Target:** Snapdragon-powered PC / Snapdragon X Series.
- **Model:** OpenAI CLIP ViT-B/32.
- **Planned runtime:** Qualcomm AI Runtime or a supported ONNX Runtime path, subject to model/operator compatibility testing.
- **Validation:** not yet performed on Snapdragon hardware.

`snapdragon/clip_export.py` exports the embedding path to ONNX on CPU; an exported file is not proof of target compatibility or acceleration. The optional `snapdragon/qai_hub_profile.py` script requires `qai-hub`, `QAI_HUB_API_TOKEN`, an exported model, network access, and an exact device name from `qai-hub list-devices`. Configure the token in the PowerShell process only when submitting a real job; `.env.example` contains an empty placeholder. Normal application startup does not require this token. There is no project-specific AI Hub job result to claim.

## Limitations

CLIP has not been evaluated on a representative industrial dataset, so no industrial diagnostic accuracy is claimed. Relative similarity is not a diagnosis. Snapdragon execution, NPU acceleration, ONNX compatibility on the target, and AI Hub profiling have not been validated. TF-IDF can miss paraphrases; review retrieved passages. Follow official equipment instructions, site procedures, risk assessment, and lockout/tagout requirements.
